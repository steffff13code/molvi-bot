## Группа A — сделать сегодня (дёшево, без замеров и аккаунтов)

### A1. Купить минимальный пакет GigaChat как физлицо (~1500 ₽, 10 минут)

**Зачем.** Бесплатные токены GigaChat по п. 2.4 соглашения Сбера разрешены
**только для личных некоммерческих целей**. Бот уже коммерческий продукт —
формально это нарушение соглашения, и Сбер может заблокировать аккаунт без
предупреждения. Резервного LLM-провайдера в коде нет (`bot/services/providers/llm.py`
знает только `gigachat`) — блокировка аккаунта останавливает продукт целиком.
Это самый дешёвый способ снять этот риск, дороже он не станет.

**Как сделать:**
1. Зайти в [GigaChat Studio](https://developers.sber.ru/studio) под тем же
   аккаунтом, к которому привязан `GIGACHAT_AUTH_KEY`.
2. В разделе тарифов купить минимальный платный пакет токенов (не бесплатный).
3. Ничего в коде менять не нужно — оплата легализует использование того же
   ключа, который уже стоит в Railway.

### A2. Секреты для деплоя сайта + смена пароля FTP (10 минут)

**Зачем.** При мёрже в `main` увидел, что workflow `deploy-site.yml` падает:
`Error: Input required and not supplied: server`. Ещё в PR-3 сервер/логин
вынесли из файла workflow в GitHub Secrets (раньше они были видны в
открытом виде в репозитории), но сами секреты в GitHub так и не добавили —
деплой сайта сломан с того момента.

**Как сделать:**
1. GitHub → репозиторий `molvi-bot` → **Settings → Secrets and variables →
   Actions → New repository secret**.
2. Добавить `FTP_SERVER` — адрес FTP-сервера reg.ru (тот, что был раньше
   захардкожен в `deploy-site.yml`, посмотрите в истории git до PR-3, или
   возьмите из панели reg.ru).
3. Добавить `FTP_USERNAME` — логин FTP.
4. **Сменить пароль FTP** в панели reg.ru — старый пароль ходил открытым
   текстом при каждом деплое до PR-3, считайте его скомпрометированным.
5. Добавить новый пароль как секрет `FTP_PASSWORD` (workflow уже на него
   ссылается).
6. Проверить: сделать любой пустой коммит в `site/` или вручную запустить
   workflow «Deploy site to reg.ru» (вкладка Actions → выбрать workflow →
   Run workflow) — должен пройти зелёным.

### A3. Решить, мёржить ли `feat/molvi-v3` в `main`

**Зачем.** Ветка `feat/molvi-v3` (атрибуция источников, LLM-инфраструктура,
надёжность при рестарте, дашборд) готова, CI зелёный на каждом коммите, но
в `main` (то, что реально крутится на Railway) не влита — решение о мёрже
сознательно оставлено за вами.

**Как сделать:** посмотреть PR (если ещё не открыт — попросите открыть) или
сравнить ветки на GitHub: `https://github.com/steffff13code/molvi-bot/compare/main...feat/molvi-v3`.
Если устраивает — смёржить самостоятельно кнопкой на GitHub, либо попросите
следующую сессию сделать это за вас явным «влей feat/molvi-v3 в main».

### A4. Проверить переменные окружения на Railway после мёржа (5 минут)

**Зачем.** Значения из `.env` могут только *понижать* лимиты в коде, никогда
не поднимать — но если на Railway годами стоят старые/неверные значения,
стоит свериться руками хотя бы один раз.

**Как сделать:** Railway → проект → сервис бота → **Variables**, свериться
со свежим `.env.example` в репозитории. Особое внимание:
- `MAX_AUDIO_MB` — рекомендовано `20` (потолок самого Telegram Bot API,
  больше код всё равно не пропустит, но лучше не держать в переменной
  вводящее в заблуждение большое число).
- `MAX_DURATION_SEC` — можно смело поднять до `7200` (2 часа) — с PR-6
  обрезка идёт через `ffmpeg`, память больше не растёт с длиной записи.
- `SBER_VERIFY_SSL` — должно быть `true` (или не задано — `true` дефолт
  в коде с PR-7). Если раньше стояло явное `false` — уберите переменную.
- После мёржа `feat/molvi-v3` — `GIGACHAT_BASE_URL` можно не задавать
  (дефолт `https://api.giga.chat` уже в коде), но если раньше в Railway
  был явно прописан старый адрес `gigachat.devices.sberbank.ru` —
  **обязательно удалите эту переменную**, иначе новый код продолжит
  ходить на старый адрес, где GigaChat 3 Ultra недоступен.

## Группа B — замер прода (нужен, чтобы разморозить PR-10 — цены)

### B1. Прогнать скрипт замера против боевой БД (15–30 минут)

**Зачем.** `docs/BASELINE.md` прямым текстом говорит: PR-10 (цены ×2 и
снижение бесплатного лимита 60→15 минут) заблокирован, пока в нём не
появится `AVG(minutes_used)` — без этой цифры нельзя выбрать между
сценарием ×2 и ×2,5. Это единственный шаг, который физически нельзя
сделать без доступа к продовой базе.

**Как сделать:**
1. Получить доступ к БД на Railway. Если БД — `DB_PATH` на смонтированном
   Volume (см. `docs/BASELINE.md`, раздел про `DB_PATH`): либо подключиться
   через `railway run` / `railway shell` из CLI Railway, либо скачать файл
   БД через Railway Volume UI.
2. Прогнать один из двух готовых скриптов (лежат в репозитории):
   ```bash
   # вариант 1 — Python, печатает готовый markdown-блок
   python scripts/prod_baseline.py

   # вариант 2 — чистый SQL, если Python недоступен на месте
   sqlite3 /путь/к/прод/molvi.db < scripts/prod_baseline.sql
   ```
3. Результат вставить в `docs/BASELINE.md` вместо `_ожидает замера_` в
   разделах 1–6 (там же указано, дата и кто измерял).
4. Отдать результат следующей сессии Claude Code с фразой вроде «вот замер
   прода, продолжай PR-10» — дальше цены и `FREE_MINUTES` посчитаются и
   применятся синхронно в `bot/services/pricing.py`, `bot/keyboards/inline.py`
   и на сайте автоматически, без дополнительных решений с вашей стороны
   (порог уже прописан: `AVG(minutes_used) > 38` → сценарий ×2,5, иначе ×2).

## Группа C — юридические реквизиты (нужны для легализации и приёма платежей)

### C1. Заполнить реквизиты ИП в 4 документах (30 минут)

**Зачем.** PR-8 вставил маркеры вместо реальных данных — без них документы
физически не могут считаться вступившими в силу, и ЮKassa не подключит
приём платежей по оферте с плейсхолдерами.

**Что заменить** (ищется по всему сайту как `ЗАПОЛНИТЬ_*`):

| Маркер | Что вписать |
|---|---|
| `ЗАПОЛНИТЬ_ФИО` | ФИО индивидуального предпринимателя целиком |
| `ЗАПОЛНИТЬ_ОГРНИП` | номер ОГРНИП |
| `ЗАПОЛНИТЬ_ИНН` | ИНН |
| `ЗАПОЛНИТЬ_АДРЕС` | юридический адрес ИП |
| `ЗАПОЛНИТЬ_EMAIL` | рабочий e-mail для обращений и возвратов |
| `ЗАПОЛНИТЬ_ТЕЛЕФОН` | контактный телефон |
| `ЗАПОЛНИТЬ_ДАТА` | дата, с которой редакция документов вступает в силу (сегодняшняя или ближайшая удобная) |

**Где именно** — 4 файла в `site/legal/`:
`privacy/index.html`, `terms/index.html`, `offer/index.html`, `consent/index.html`,
плюс подвал ещё 6 страниц (`site/index.html`, `site/transcribe/index.html`,
`site/blog/index.html` и 3 статьи блога) — туда реквизиты уже подставлены
шаблоном, изменить нужно только в 4 юридических файлах, подвал подтянется
той же строкой автоматически, если правите find/replace по всему `site/`.

**Как сделать без правки кода руками:** отдайте список готовых значений
(ФИО/ОГРНИП/ИНН/адрес/e-mail/телефон/дата) следующей сессии Claude Code —
она сделает `grep -rl "ЗАПОЛНИТЬ_"` и заменит везде одним коммитом.
Либо самостоятельно: открыть каждый файл, `Ctrl+F` → `ЗАПОЛНИТЬ_` → заменить.

### C2. Договор-поручение с Nexara (152-ФЗ, ч. 3 ст. 6)

**Зачем.** Распознавание речи фактически идёт через Nexara (не через
Сбер) — это уже отражено в тексте privacy/consent (PR-8). Но по закону
одного упоминания в тексте недостаточно: передача персональных данных
обработчику законна только при заключённом договоре-поручении. Без него
даже с исправленным текстом согласия передача данных в Nexara формально
незаконна.

**Как сделать:** написать в поддержку Nexara (сайт `nexara.ru` или
аналогичный контакт из вашего личного кабинета) с запросом на подписание
договора-поручения на обработку персональных данных как оператора-
обработчика — обычно у сервисов такого рода есть готовая форма/шаблон.
Юридическая консультация здесь может понадобиться, если готового шаблона
у Nexara нет.

### C3. Уведомление в РКН об обработке персональных данных

**Зачем.** ИП, обрабатывающий персональные данные (а бот их обрабатывает —
голос, транскрипты, Telegram ID), обязан подать уведомление в
Роскомнадзор. Номер оператора после этого нужно будет добавить в подвал
сайта (место уже подготовлено рядом с ОГРНИП/ИНН).

**Как сделать:** подать уведомление через
[pd.rkn.gov.ru](https://pd.rkn.gov.ru/) (личный кабинет оператора ПДн,
нужна регистрация через Госуслуги). После получения номера — сообщите
его следующей сессии, чтобы добавить в подвал сайта.

## Группа D — аккаунты и интеграции

### D1. Завести счётчик Яндекс.Метрики (10 минут; нужно поставить ЗАРАНЕЕ)

**Зачем.** Без Метрики нельзя измерить, откуда приходят пользователи и что
на сайте работает, а без неё сейчас нельзя запускать рекламу вообще. Ставить
нужно **за 3–5 дней до** переноса лендинга (`/transcribe/` → `/`, следующий
шаг после Метрики), чтобы накопить базовую линию на старом URL до переезда.

**Как сделать:**
1. Зарегистрировать счётчик на [metrika.yandex.ru](https://metrika.yandex.ru/)
   для домена `molvi-ai.ru`.
2. Включить в настройках счётчика: Вебвизор, карту кликов (clickmap),
   отслеживание переходов по ссылкам (trackLinks), точный показатель отказов
   (accurateTrackBounce).
3. Скопировать номер счётчика (это единственное, что нужно от вас руками —
   сам код на страницы и 4 цели вставит следующая сессия).
4. Отдать номер счётчика следующей сессии Claude Code.

### D2. Зарегистрировать ЮKassa и пройти модерацию (несколько дней)

**Зачем.** Это платёжный шлюз для приёма рублёвых платежей на сайте — без
него нет способа получить деньги за пределами Telegram Stars.

**Как сделать:**
1. Зарегистрироваться на [yookassa.ru](https://yookassa.ru/) как ИП,
   подключить магазин.
2. **Перед подачей на модерацию обязательно сделать пункт C1** (заполнить
   реквизиты в оферте) — иначе отказ почти гарантирован. Также в оферте до
   сих пор упоминается продажа физического устройства, которого не
   существует — это тоже основание для отказа, эту правку следующая сессия
   должна сделать до подачи на модерацию (сообщите заранее, если ещё не
   сделано).
3. Получить `shop_id` и `secret_key` после одобрения.
4. Передать их следующей сессии для настройки `/webhook/yookassa` — эта
   часть (сам платёжный контур в коде) ещё не реализована, планируется
   отдельным шагом (PR-14) и требует именно этих двух значений на входе.
5. Если модерация отказывает — запасной вариант: Robokassa (карты 3,9% /
   СБП 2,7%). Продамус не рассматривать — 10 000 ₽ на входе без гарантии
   конверсии.

### D3. Поддомен `pay.molvi-ai.ru`

**Зачем.** Домен, с которого идёт оплата, должен совпадать с доменом,
на котором опубликована оферта (`molvi-ai.ru`) — иначе ЮKassa при
модерации может завернуть заявку, посчитав несовпадение доменов
подозрительным.

**Как сделать:** в DNS-панели домена `molvi-ai.ru` добавить A/CNAME-запись
`pay` → на IP/домен, который выдаст Railway для этого сервиса (появится,
когда будет готов код платёжного контура — можно сделать заранее, указав
временную заглушку, или отложить до момента, когда код PR-14 будет готов).

### D4. Российский корневой сертификат (или подтвердить, что не нужен)

**Зачем.** С PR-7 бот по умолчанию строго проверяет TLS-сертификат Сбера
(`SBER_VERIFY_SSL=true`). Если сертификат Сбера подписан российским
корневым CA (НУЦ Минцифры), а не публичным — проверка может начать
падать без этого бандла. Скачать его не удалось — сеть песочницы этой
сессии блокирует `gu-st.ru`.

**Как сделать:**
1. Сначала просто проверьте — после мёржа `feat/molvi-v3` (там сменился
   `GIGACHAT_BASE_URL`) отправьте боту одну запись на расшифровку. Если
   саммари приходит нормально — сертификат не нужен, можно закрыть пункт.
2. Если ловите ошибку SSL/TLS в логах Railway при вызове GigaChat —
   скачайте `russian_trusted_root_ca_pem.crt` с официального источника
   (Минцифры / `gosuslugi.ru` / `reestr-pki.gov.ru`, инструкция и точная
   ссылка — в файле `assets/certs/README.md` в репозитории).
3. Положите файл в `assets/certs/russian_trusted_root_ca_pem.crt`
   (закоммитьте или загрузите на Railway как volume-файл).
4. В Railway Variables добавьте
   `SBER_CA_BUNDLE=assets/certs/russian_trusted_root_ca_pem.crt`.

## Группа E — для будущих шагов (не блокируют то, что уже сделано)

### E1. Доступ к GigaChat 3 Ultra и Lite + рабочий ключ для замера (PR-17)

**Зачем.** Следующий шаг по плану — экспериментально проверить, можно ли
получить нужное качество саммари одним вызовом на модели покрупнее (Ultra)
вместо постройки многоходового конвейера (это 80+ часов работы, которую
очень хочется не делать, если в ней нет необходимости). Без реального
платного доступа к Ultra/Lite и без боевого `GIGACHAT_AUTH_KEY` этот замер
провести нельзя — в песочнице сессии его нет.

**Как сделать:** подтвердить, что на аккаунте GigaChat, привязанном к
`GIGACHAT_AUTH_KEY`, есть доступ к моделям `GigaChat-3-Ultra` и
`GigaChat-2-Lite` (может потребоваться отдельное включение в личном
кабинете/тарифе). Дать знать следующей сессии, что можно проводить замер —
код для него (`scripts/eval_prompts.py`, эталоны) ещё предстоит написать
в PR-17, но без доступа к моделям сам эксперимент бессмысленен.

### E2. `API_ID` / `API_HASH` Telegram для Local Bot API Server (PR-21)

**Зачем.** Сейчас потолок размера файла — 20 МБ (жёсткое ограничение
обычного Telegram Bot API). Чтобы поднять его до 2 ГБ, нужно поднять
собственный Local Bot API Server — а для него Telegram требует `API_ID` и
`API_HASH` (это не то же самое, что `TELEGRAM_BOT_TOKEN`).

**Как сделать:**
1. Зайти на [my.telegram.org](https://my.telegram.org/apps) под тем же
   Telegram-аккаунтом, что использовался при создании бота (или любым
   вашим личным).
2. Создать приложение (Api development tools → Create new application) —
   понадобится только название и краткое описание, любые.
3. Скопировать `api_id` и `api_hash`.
4. Передать следующей сессии — это отдельный шаг (PR-21), не блокирует
   ничего из уже сделанного, можно отложить до появления жалоб
   пользователей на файлы больше 20 МБ.

## Коротко: что сделать в первую очередь

1. **A1** (пакет GigaChat, 1500₽) — снимает риск блокировки всего продукта, 10 минут.
2. **A2** (секреты FTP) — без этого сайт не деплоится вообще.
3. **A3** (решение по мёржу `feat/molvi-v3`).
4. **B1** (замер прода) — разблокирует цены, самый долгий шаг из «дешёвых».
5. **C1** (реквизиты в документах) — нужно и для легальности, и для подачи в ЮKassa.
6. Остальное (D, E) — по мере готовности, ничего из уже сделанного не блокирует.
